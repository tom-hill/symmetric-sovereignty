## Statuses
`draft` → `ready` → `published` → responses logged in [[Encounters Index|75 Encounters]]

**Where things live:**
- `15 Published/Drafts/` — a piece while it is being written. Never public.
- `15 Published/` — a piece once it is published: moved up out of `Drafts`, with `status: published`. Promotes to the public repo.
- `15 Published/Notes/` — each piece's `Notes — <title>` formatting handover: anything the person or agent converting it needs to know — callouts that must become styled asides, deliberate typography, links that must survive. Editorial commentary never lives in the publishable file. Never public.

→ [[Publishing — the Website Side]] for how a piece becomes a page on reyor.co.uk.

## The rule that makes this a loop, not an archive
A piece is not finished when it is published. It is finished when whatever came back has been logged as an encounter, and any question it raised exists as an `OQ` or a `UQ`. Otherwise the public layer is a broadcast rather than a test, and the point of publishing was to be tested.

## The two repositories

**Private — the system of record.** `/Users/tomhill/Documents/Git/Symmetric Sovereignty`, everything, one commit per session.

**Public — https://github.com/tom-hill/symmetric-sovereignty** — 115 notes, receiving only promoted content. Created 2026-09-16.

Promote with `./.tools/publish.sh`, then review the diff and push. The script only ever writes private → public, and publishes only the whitelist. Excluded and why:

|---|---|
| `50 Notebook`, `90 Assets` | The handwritten notebook. Where the thinking is done and where being wrong in private is the point |
| `70 Threads` | Dialogue transcripts — personal and commercial throughout |

| `00 Index/Provenance` | References the private journal |
| `15 Published/Drafts` | A draft becomes public when it is published, not while it is a draft |
| `15 Published/Notes` | Formatting handovers — commentary about a piece, not the piece |
| any `type: publication-notes`, or `type: publication` with `status: draft` | The same two rules by frontmatter, so a misfiled file is still held back |
| `80 Ways of Working/Tools.md` | Live commercial channels |
| `Claude/Findings` | Weekly operational analysis; churns, and cites private notes |

`20 Open Questions` and `25 Unasked Questions` promote **by default** — the questions are what Tom committed to publishing openly, and they carry the least friction of anything here.

**The rule that must not break:** the public repo only ever *receives*. Never make the private repo public — its history carries everything that was ever in it.

> [!claude]
> The friction is the risk. [[Thread — Outreach Avoidance]] already diagnosed avoidance of publishing, and "not promoted yet" is a comfortable new costume for it. If two sessions pass with nothing in the `published` state, that is the avoidance, not a scheduling problem.
